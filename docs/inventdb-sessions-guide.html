Claude Code Session Store

Installing and operating inventdb-sessions — the plugin that mirrors Claude Code sessions into InventDB as a queryable execution record, and queries them back over MCP.

tools/claude-code-sessions/inventdb-sessions-guide.html · August 2026 · plugin v0.1.0 · status: working

What this is

A session log is not a transcript — it is an execution record: every command with its output, every file’s pre-edit state, every approach that was tried and abandoned. It is the only engineering artifact that contains the work which failed, and Claude Code deletes it after 30 days by default (cleanupPeriodDays). This plugin captures it into InventDB and makes it searchable by the whole team.

1 · Scope & boundaries

Two boundaries decide everything else. Read them before planning a rollout.

Capture works on Claude Code only

Hooks are a Claude Code feature, and Claude Code is the only surface that writes local session transcripts. Everywhere else, session data lives server-side and there is no lifecycle event to hook.

SurfaceLocal transcriptsHooksMCPResult
Claude CodeyesyesyesCapture + query
Claude DesktopnonoyesQuery only
Claude web / Work / TeamsnonoyesQuery only

It mirrors; it does not replace local storage

--resume, --continue, the session picker, /rewind and compaction all read ~/.claude/projects/<project>/<session-id>.jsonl directly from disk — and the shipper reads those same files as its source. There is no hook event for listing or loading a session, so the local store cannot be redirected. InventDB is the queryable archive; the local files remain the working store. Never lower cleanupPeriodDays or delete transcripts as part of an install.

2 · How it works

Two independent halves, deliberately using different transports.

PathMechanismWhy that mechanism
Write 5 async hooks → ship-session.mjs → REST bulk Fidelity requires tailing the local .jsonl, which only a local process can do. An MCP tool cannot read the user’s disk when the instance is remote.
Read InventDB MCP server (sql, search, get, schema) Lets Claude query every past session mid-conversation. More useful than a session picker, because the real question is semantic or aggregate rather than a list of session UUIDs.

The shipper tails each transcript from a persisted byte watermark and bulk-inserts new lines. The watermark advances only after a successful write, so an interrupted or failed run resumes at the exact byte — no gaps, no duplicates. Re-running a fully-synced transcript inserts 0 rows.

tools/claude-code-sessions/
├── .claude-plugin/plugin.json   plugin manifest
├── .mcp.json   InventDB MCP server (read path)
├── hooks/hooks.json   5 async capture hooks (write path)
├── scripts/ship-session.mjs   the shipper
└── skills/inventdb-sessions/SKILL.md   /inventdb-sessions

Config and state live in ~/.claude/inventdb-sync/, never inside the plugin — the plugin directory is versioned and replaced on update, which would destroy watermarks and place credentials in a distributed tree.

3 · What gets captured

<ns>.session_line — one row per transcript line

ColumnMeaning
session_id, seqSession id and monotonic line index
ts, kind, role, modelTimestamp; line type (user/assistant/attachment/…); message role; model id
titleClaude Code’s own derived session name, from its ai-title lines. Sessions are retitled as they develop, so several are emitted — the highest seq is the current name.
last_promptText of the session’s last-prompt line
cwd, git_branch, cc_versionWhere and on what the work happened
source_file, agent_id, parent_sessionProvenance. Subagent and workflow transcripts embed their parent’s session id, so the file path is the only thing that distinguishes them.
attachmentsCount of inline binaries on that line (repeated on each chunk of a chunked line; files upload once, against chunk_idx = 0)
uuid, parent_uuid, request_id, is_sidechain, bytes, chunk_idx, chunk_nIdentity, threading, size and chunking
rawThe original line, byte-exact

Attachments

Inline base64 payloads — pasted screenshots, images returned inside tool results — are uploaded as real InventDB attachments on the row that carried them, named <session>-<seq>-<n>.<ext>, and enter the normal extraction and embedding pipeline. raw still holds the original bytes: the attachment is additional, never a replacement, so the archive can always reconstruct the original line.

GET /attach/<ns>/session_line/<record _id>      # or the MCP attach_list tool

<ns>.session_event — one row per lifecycle event

session_id, event, ts, cwd, transcript_path, permission_mode, source, reason, host.

4 · Installation — four scenarios

A · Local directory — works today

Point Claude Code at an unpacked copy of the plugin. This needs no marketplace and no network, and is the supported path for air-gapped installs.

claude --plugin-dir <path-to>/claude-code-sessions

# or register the directory that contains it as a marketplace
/plugin marketplace add <path-to-checkout>
/plugin install inventdb-sessions@inventdb

B · Marketplace — for team rollout

Requires a published marketplace

/plugin marketplace add clones the source repository on the user’s machine, so the repository must be readable by that user. Substitute your published plugin repository below — a marketplace pointing at a private repository fails to clone for everyone who lacks access, which is most customers.

/plugin marketplace add <org>/<plugin-repo>
/plugin install inventdb-sessions@inventdb
/inventdb-sessions setup https://acme.inventdb.com

To pre-register it for everyone working in a repo, commit to .claude/settings.json:

{
  "extraKnownMarketplaces": {
    "inventdb": { "source": { "source": "github", "repo": "<org>/<plugin-repo>" } }
  },
  "enabledPlugins": { "inventdb-sessions@inventdb": true }
}

A marketplace can also be served from a URL or an npm package rather than a git repository, which avoids exposing any source tree at all.

C · Skill only, no plugin

The skill installs the hooks into settings.json itself, so this works without the plugin system.

cp -r tools/claude-code-sessions/skills/inventdb-sessions ~/.claude/skills/
mkdir -p ~/.claude/inventdb-sync
cp tools/claude-code-sessions/scripts/ship-session.mjs ~/.claude/inventdb-sync/

# then, in Claude Code
/inventdb-sessions setup <url>

Use ~/.claude/skills/ for personal scope, or .claude/skills/ inside a repo to commit it for a team.

D · Enterprise rollout

Deploy through managed settings (managed-settings.json, MDM, or the ClaudeCode registry key), and allowlist the MCP server with allowedMcpServers.

Use the plugin route in enterprise

strictPluginOnlyCustomization blocks hooks from every non-plugin source, and allowManagedHooksOnly ignores user and project hooks entirely. Under either flag a settings-based install silently does nothing — no error, no capture — while a plugin install still works.

Requirements

  • Claude Code
  • node on PATH (v18+; the shipper uses global fetch). If the hook environment cannot find it, replace "command": "node" in hooks/hooks.json with an absolute interpreter path.
  • A reachable InventDB instance and credentials.

5 · Configuration

Set the target with the CLI rather than hand-editing JSON. It merges into ~/.claude/inventdb-sync/config.json at mode 0600, warns if the namespace is not a bare word, and verifies by logging in before reporting success.

node scripts/ship-session.mjs --set \
  --url https://acme.inventdb.com \
  --namespace inventdb_claude \
  --user <user> --password <pass>

node scripts/ship-session.mjs --show-config   # resolved path, secrets redacted

--token <jwt> works instead of a password. Every field is overridable by environment variable — prefer these when a password on disk is unacceptable:

INVENTDB_SYNC_BASE, INVENTDB_SYNC_NAMESPACE, INVENTDB_SYNC_USER, INVENTDB_SYNC_PASSWORD, INVENTDB_SYNC_TOKEN, INVENTDB_SYNC_CONFIG. MCP: INVENTDB_MCP_URL (<base>/mcp) and INVENTDB_MCP_TOKEN.

INVENTDB_SYNC_CONFIG is authoritative even when the file does not exist yet, which is what makes it safe to point --set at a scratch config during testing.

Two configuration rules that bite

  • Namespaces must use underscores (inventdb_claude, not inventdb-claude). A hyphen forces every SQL statement to quote the namespace.
  • Use a bearer token for MCP, not OAuth discovery. InventDB advertises OAuth on /mcp, but behind a reverse proxy the advertised resource_metadata and authorization_servers are built from the proxied Host header and point at the instance’s internal address, which no external client can reach.

Watermarks are scoped per target (state/<base>__<namespace>/). Repointing at a different instance correctly starts that target from scratch — sharing one set across instances would tell a new target that everything was already synced, so it would silently receive nothing.

7 · Querying the archive

Run these through the MCP sql tool, or POST <base>/sql.

-- Session index by NAME rather than UUID
SELECT session_id, title, ts FROM <ns>.session_line
WHERE title IS NOT NULL ORDER BY ts DESC;

-- Has anyone already debugged this error?
SELECT session_id, ts, git_branch, cwd FROM <ns>.session_line
WHERE raw LIKE '%<error text>%' ORDER BY ts;

-- What did this file look like before it was edited?
SELECT ts, session_id, raw FROM <ns>.session_line
WHERE raw LIKE '%<filename>%' AND raw LIKE '%old_string%' ORDER BY ts;

-- Sessions that captured screenshots or other binaries
SELECT session_id, seq, attachments FROM <ns>.session_line
WHERE attachments > 0 AND chunk_idx = 0;

-- Reconstruct a session in order
SELECT seq, kind, role, raw FROM <ns>.session_line
WHERE session_id = '<id>' ORDER BY seq;

raw holds the original line byte-exact, so LIKE over it searches everything — prompts, tool inputs, command output, pre-edit file contents. For fuzzy recall use the MCP search tool (BM25) or MEANING() instead.

Counting rule

To verify completeness use SELECT COUNT(*) … WHERE …, one query per file. Do not count DISTINCT values client-side from a fetched row set — /sql caps the rows it returns, so any total derived that way is unreliable.

8 · Operations & backfill

Steady state

All five hooks are async: true, so capture never blocks a turn, and the shipper exits 0 on every path — a mirror failure cannot break a session. Errors go to ~/.claude/inventdb-sync/state/sync.log, never into the session. Steady-state capture is a few KB per turn.

Backfilling history

Size it first and say the number out loud — a single developer’s history is routinely over 1 GB across more than 1,000 files, with most bytes in a handful of enormous transcripts.

find ~/.claude/projects -name '*.jsonl' | wc -l
node scripts/ship-session.mjs --all

A large import is not free

InventDB maintains indexes on write, so a bulk backfill does full property and vector indexing as it goes. On a small instance that work can saturate the server until it catches up.

Wait; do not restart the instance. Pace large loads, or start from adoption and let the archive build forward. Nothing is lost either way: a failed file resumes at the exact byte.

Expected transient failures

Sustained write load can produce occasional 5xx responses, which the shipper retries with backoff. Do not investigate these as content bugs — re-send the same batch first; if it succeeds, it was load rather than the data.

9 · Troubleshooting

SymptomCheck
Capture stopped--status first — it prints the target actually configured. The most common cause is a config repointed at a different or stopped instance.
ECONNREFUSEDThe configured instance is not running. Nothing is lost; watermarks do not advance on failure.
No errors visible anywhereThe shipper never prints into a session by design. Read state/sync.log.
Rows stopped advancing--status against the live transcript size. Then check for stale .lock files in state/, left by a killed process; they self-clear after 5 minutes.
Hooks never fireConfirm the plugin is enabled, or that the five entries are in settings.json. Open /hooks to review — the UI only reports hooks that error or run slowly, so silent success is invisible by design.
TLS connects but nothing respondsThe instance is busy indexing. Wait rather than restart.

10 · Security notes

  • Session logs contain whatever was on screen — command output, file contents, and any secrets that passed through a terminal. Treat the namespace as sensitive and scope it with row-level security; contractor and staff sessions can share one database under different access rules.
  • Credentials never enter the plugin tree. Config lives in ~/.claude/inventdb-sync/config.json at mode 0600, and config.json is gitignored repo-wide. Prefer the environment variables where a password on disk is unacceptable.
  • Capture is per-user and explicit. Nothing is captured until a target is configured, and uninstall removes the hooks while leaving data intact.

Summary. A team’s session logs are the only record that includes the work that failed — everything else in the toolchain is a record of success, written by the winner. Capture on Claude Code, query everywhere over MCP, and keep the local .jsonl files exactly where they are.
