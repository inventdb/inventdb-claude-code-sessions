Cache reads are 8,928× the uncached input, and 77× the cache writes that created them. That ratio is the single largest lever on the bill and no vendor dashboard reports it. The same SUM splits by branch, directory or model, so the spend becomes per-feature rather than one unallocatable line.

Cross-team recall

Has anyone already hit this error, and what did they try that failed?

Search across every sessionRows matched
Runtime panics — panicked at500
Compiler errors — error[E0…]198
 
SELECT session_id, ts, git_branch FROM inventdb_claude.session_line
WHERE message.content LIKE '%<error text>%';

Each match carries the diagnosis and the fix that followed it in the same session — including the approaches that were tried and abandoned. Nothing else in the toolchain keeps those; a commit history records only what worked.

Incident forensics

This broke last week. What actually changed, and what convinced us it worked?

Claude Code snapshots a file before it edits it, and those snapshots are mirrored too — so prior contents are recoverable even when the change was never committed, was squashed, or was reverted before review. The command output that was taken as proof is stored beside the change, which shows what was believed, not only what was done.

A single session reaches 82,399 rows — far past what any context window holds, so the archive is the only complete copy. The three compact restarts matter most: detail that left the live context on compaction is still queryable in the mirror afterwards. Local transcripts are per-machine and expire on a retention timer; the archive is neither.

8
Mining sessions into durable artifacts

What can we harvest from all this so the learning outlives the session?

HarvestableCount
Rows carrying inline binaries748
Screenshots & diagnostics stored as attachments762
Sessions tied to a shipped pull request877
Titled sessions usable as a work index14,316

The archive is a corpus. It generates runbooks and decision records from how work was really done, harvests recurring corrections into project instructions, and yields evaluation sets built from genuine failures rather than synthetic ones. Binaries are uploaded as real InventDB attachments on the row that produced them, so evidence stays joined to its context.

How to read these numbers. Each figure is a single COUNT(*) or SUM under an explicit predicate against the live instance, taken on 29 August 2026. The archive is written to continuously by live capture, so totals move between queries — treat them as a reading, not a constant. Row counts reconcile exactly with the shipper’s own watermarks (506 files, 281,082 lines). Branch names and directory paths are redacted; the query shapes are real.

On the companion page. ten-uses.html is an earlier snapshot of this same archive, stamped 23 August 2026, and its totals are larger — 407,063 rows from 694 source files. The namespace was rebuilt and re-imported between the two readings, and a re-import can only read transcripts that still exist on disk, so sessions whose source files had already passed the local retention timer are not present in this one. The two pages do not disagree; they bracket that event.
